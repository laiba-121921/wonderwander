# CLAUDE.md: wonderwander

Engineering rules for working on this repository. The app is a phone-first philosophy training PWA: the code is here and public; the curriculum it teaches is a separate, private content pack (`docs/CONTENT_PACK.md`). `docs/ARCHITECTURE.md` explains how the pieces fit.

## Rules

1. **No em dashes or en dashes anywhere**: UI copy, code comments, commit messages, docs, prompts, and LLM output shown to the user. Use commas, colons, parentheses or "to". Hyphens in compound words are fine. `npm run lint` checks source; a runtime sanitiser cleans LLM output.
2. **Never write philosophy content.** Lessons, drills, keys, cards, playbooks, readings and prompts come from a content pack. Never invent, reword or fill gaps. Test fixtures that need text use neutral, everyday placeholders.
3. **No curriculum text in this repository.** Tests that need the real curriculum read it from `content/` at run time (`tests/content.ts`) and skip when it is absent. `npm run lint` fails on any copied run of curriculum text (`scripts/check-curriculum.ts`).
4. **Prompts are verbatim.** The Gemini prompts in `supabase/functions/llm/prompts/` are generated by `scripts/sync-prompts.ts`; only slot syntax and the clearly marked transport suffixes may differ from the source.
5. **Zero budget.** Free tiers only: GitHub Pages, Supabase free, Gemini API free tier. No dependency that needs a paid key.
6. **The repository is public.** Never commit secrets, `.env` files, API keys or user data. Only the Supabase URL and the publishable key reach the client, through build variables. Each person's Gemini key stays encrypted on their own phone.
7. **Phone first.** Every screen is designed for Android Chrome at 360 to 412 px wide and tested at 390 by 844.
8. **British spelling** in all UI copy (scepticism, behaviour, organise).

## How to work

- Write tests alongside code. Pure logic (escalation, lockout dates, mastery, gating, FSRS mapping, parsers, logic generators) must be unit tested.
- A test command passing means its exit code is 0, not only that the summary line says "passed".
- Database changes are new migrations in `supabase/migrations/`; never edit an applied one. After each, run the checks in `supabase/tests/` (every line ends in "ok").
- Verify anything time-sensitive (model ids, free-tier limits, library versions) before relying on it, and note it in `docs/VERIFIED.md` with the date.
- Commit messages are plain and contain no dashes.

## Commands

Node 24 or newer.

- `npm run setup`: for a new instance, checks tools and writes `.env.local` (`docs/SELF_HOST.md`)
- `npm run dev`: local dev server
- `npm run test`: unit tests (Vitest)
- `npm run test:e2e`: Playwright at 390 by 844 against a fake Supabase (needs the content checked out at `content/`)
- `npm run test:pwa`: the production build in content pack mode, with the service worker (needs the content)
- `npm run lint`: ESLint, the dash check, the secret check and the curriculum check
- `npm run content`: parse `content/raw` into `content/json` (with the content checked out)
- `npm run pack` and `npm run upload-pack`: build and publish a content pack (`docs/CONTENT_PACK.md`)
- `npm run fingerprints`: refresh the curriculum fingerprints after the curriculum changes
- `npm run build`: production build
